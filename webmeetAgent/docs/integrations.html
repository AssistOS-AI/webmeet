Integrations

WebMeet relies on explicit service boundaries rather than duplicating Explorer, media, document, or agent-runtime responsibilities inside the room control plane.

Explorer Host Shell

Explorer loads the WebMeet plugin and shared runtime components, supplies authenticated workspace identity, and remains the authority for workspace files. WebMeet's public plugin assets are exposed through the manifest route for /IDE-plugins/webmeet-tool-button/*; the standalone room loader is exposed through the room-scoped guest route.

The browser room loader imports WebSkel from Explorer's shared library path. SCRIPTA file creation, canonical Markdown, Automerge state, and document deletion remain Explorer operations invoked through its internal allowlist.

LiveKit Infrastructure

webmeetInfra/liveKitServerAgent provides signaling, media transport, participant presence, data channels, Redis coordination, TURN/STUN, and production TLS. WebMeet requests private, generation-bound operations for join material, room closure, and agent dispatch.

The manifest enables the LiveKit service without waiting for it to complete startup. WebMeet keeps room authorization and durable data independent from LiveKit's active-session state.

Meeting Secretary

The manifest enables webmeetScribeAgent as the text-only Meeting Secretary runtime. Only the complete delegated principal agent:AchillesIDE/webmeetScribeAgent can use the internal secretary operations and the corresponding SCRIPTA participant path.

The secretary consumes transcript checkpoints and returns reconciled Markdown. Explorer performs the actual Automerge merge and canonical document commit, while WebMeet owns session leases, queues, recovery journals, room attachment state, and participant-visible activity.

Optional Room Agents

webmeetLivekitAiAgent can be dispatched into a room as a self-hosted LiveKit AI participant. WebMeet stores dispatch metadata and exposes attach, list, and detach operations; the LiveKit worker owns its media participation.

webmeetStt supplies private speech-to-text for internal agent workflows where required. Browser push-to-talk commands and Meeting Notes browser recognition do not create a public speech endpoint on this agent.

Ploinky Runtime

Ploinky starts the container, generates or shares declared secrets, mounts persistent agent data, provides invocation identity, and routes configured tool operations. WebMeet does not trust client-provided identity fields in place of the authenticated runtime context.
