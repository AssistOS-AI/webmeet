Documentation / Architecture

Architecture

WebMeet separates workspace navigation, protected meeting state, realtime media, and collaborative document ownership so each service controls the data and operations within its domain.

Runtime Boundaries

flowchart LR
  Explorer[Explorer host shell] -->|opens plugin and supplies identity| WebMeet[WebMeet control plane]
  WebMeet -->|private media operations| LiveKit[LiveKit media service]
  WebMeet -->|room events and protected state| Store[Encrypted room store]
  WebMeet -->|authorized document operations| Scripta[Explorer-owned SCRIPTA and Automerge]
  WebMeet -->|dispatch and reconciliation| Agents[Meeting Secretary and optional room agents]
  LiveKit -->|audio, video, screen share, data| Browser[Participant browsers]
  WebMeet -->|room projections and commands| Browser

WebMeet coordinates meeting state while media and collaborative documents remain with their owning services.

Control Plane And Durable State

The agent owns room creation, admission, roles, archives, deletion, guest scope, chat records, resources, Blackboard state, and room-agent dispatch metadata. Room payloads are encrypted with AES-256-GCM and per-room data keys wrapped by PLOINKY_WEBMEET_MASTER_KEY. The central WEBMEET_EVENT_TYPES contract separates persisted events from realtime-only events and is shared by store and browser code.

LiveKit presence is not the durable room directory. WebMeet reconciles active media participation with its authorized participant state and keeps browser-facing projections free of private DPU profile data.

Blackboard And RoboTeam Ownership

The Blackboard workspace is authoritative WebMeet room state. It is stored beneath the room-owned RoboTeam agent record in the encrypted payload because RoboTeam initializes and operates the collaboration surface, but the board is not model memory and is not owned by an LLM. webmeetAgent remains the persistence, authorization, revision-ordering, and history authority.

RoboTeam is the room assistant and orchestration boundary above that state. It exposes administrator-managed collaboration settings and converts participant interface actions, deterministic events, and natural-language requests into one validated Blackboard mutation stream. Its logical roster projection is separate from LiveKit media agents, and its commands cannot bypass WebMeet authorization or Explorer's ownership of attached files and SCRIPTA replicas.

Media Plane

webmeetInfra/liveKitServerAgent owns LiveKit signaling, microphone, camera, screen share, Redis coordination, TURN/STUN, and production TLS. WebMeet obtains generation-bound private operations and short-lived join material rather than publishing an alternative media-control path.

Leaving a room stops local capture and remote playback before exit completes. A refreshed join recreates the LiveKit connection and restores microphone and camera state; browser security requires a new user gesture before screen sharing can resume.

Collaborative Documents

SCRIPTA documents and their canonical Automerge working state remain Explorer-owned. Markdown is the durable portable materialization. WebMeet stores room attachments, active document references per board, document-scoped presentation state, and safe projections, then calls Explorer for create, open, incremental collaboration, semantic mutation, and delete operations.

Explorer also provides TinyMDE for ordinary Markdown source editing. TinyMDE emits incremental text changes, while SCRIPTA emits semantic and incremental variant operations; both use Explorer's Markdown CRDT authority. The interfaces remain separate, but WebMeet never parses or overwrites canonical Markdown.

Browser Application

The room loader initializes WebSkel from the shared Explorer library and mounts the WebMeet application. The browser combines room projections, LiveKit tracks, chat, Blackboard, SCRIPTA, media controls, and room settings while all authoritative mutations continue through the agent's configured tool boundary.
