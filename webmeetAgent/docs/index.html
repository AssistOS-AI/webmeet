WebMeet Agent Documentation

The blackboard uses CRAP visual hierarchy: aligned control groups separated only by proximity and fine vertical rules, without visible group labels or card backgrounds; stronger contrast between shell, toolbar, and canvas; a trailing appearance control; and a concise empty-canvas prompt.

WebMeet Agent owns workspace meeting rooms, guest invite routing, LiveKit participant token issuance, AI dispatch metadata, room resources, and the Explorer WebMeet plugin. Live microphone, camera, screen share, Redis coordination, TURN/STUN, and production LiveKit TLS are owned by webmeetInfra/liveKitServerAgent. Authenticated clients receive workspace room-list and roster events without reloading. WebMeet events use the central WEBMEET_EVENT_TYPES contract and the canonical room:type:base64url_payload format; each event type declares whether it is persisted or realtime-only. Authenticated LiveKit joins carry the workspace user id in participant attributes, and clients publish a sanitized avatar projection into the WebMeet roster so remote cards can render profile avatars without reading another user's DPU My Space. Media-only LiveKit updates such as microphone and track changes preserve already projected avatars. Room exit shuts down local capture and remote playback before completing the leave flow. The optional self-hosted LiveKit AI worker runs as the separate webmeetLivekitAiAgent Ploinky agent. WebMeet chat treats provider-looking text such as @open-interpreter as ordinary meeting chat; provider routing belongs to AchillesCLI Copilot.

WebMeet audio defaults to a browser-local automatic voice pipeline for users without saved preferences. It uses locally vendored RNNoise when supported, conservative adaptive gain and hum detection, standard browser processing as fallback, and local remote-participant volume normalization. Manual audio-control edits switch the draft from automatic to custom instead of limiting the user. No paid/cloud denoise service or per-minute audio processing is required, and raw audio is never persisted by diagnostics.

RoboTeam exposes workspace-backed SCRIPTA collaboration through one canonical blackboard event path and one singleton scripta-document widget. The blackboard panel composes dedicated generic, graphics, Poll/Bullets, SCRIPTA action, and SCRIPTA rendering modules. Repeated SCRIPTA structure is declared in inert WebSkel component templates, click commands use data-local-action, and cloned templates receive untrusted document values through escaped textContent rather than interpolated HTML. Poll, Bullets, and SCRIPTA widgets expose the standard eight resize handles and persist their geometry, with minimum sizes of 260 by 132, 320 by 190, and 600 by 400 pixels respectively. The blackboard uses horizontal or vertical scrolling when positioned widgets extend beyond the visible area. CSS-only overflow spacers reserve 10 pixels below widgets and 40 pixels on the right for contextual controls, while top and left receive 10 pixel margins; no JavaScript scroll-extent calculations are used. Wheel input over SCRIPTA is routed to the blackboard while that surface can still move, without removing the document's own boundary scrolling. The SCRIPTA header exposes chapter creation through a compact, visibly button-styled Chapter label followed by a plus icon. Its paragraph mode uses Explorer's whitelisted shared variants component, also used by Advanced Editor; it provides a dedicated Document return action and a Paragraph-labelled Prev/Next group that disables at document boundaries. Generated Chapter/Paragraph ordinals are visually subordinate to editable prose through small muted monospace text without badge styling. WebMeet maps canonical p-variant-* add, edit, delete, vote, and reformulation UI events back to RoboTeam instead of persisting through the component. All admitted participants may vote, while Explorer authorizes edit and delete only for the participant who added that variant. Vision, Plan, and General are creation templates for the same document format; only Vision and Plan request a work objective for generated initial content. The deterministic /event <action> [JSON object] form is parsed locally without AI, while other natural /event and /robo text is interpreted in any language by an isolated Ploinky MainAgent executing the local blackboard-event code skill. AI interpretation has a bounded lifetime so its audit finishes with an error on timeout instead of remaining pending. Chat commands and widget actions both call webmeet_event_command, carry optimistic board versions, and create one pending-to-final event audit entry. Full chat renders the sanitized semantic projection as /event <action> [payload], without transport identifiers. An authenticated read-only picker excludes runtime and dependency trees, lists workspace folders, and provides a searchable selection containing only Markdown .md files; guests can operate on room-attached resources without receiving workspace paths or tree access. Chat defaults to Normal and offers one Full switch: off hides command traffic, while on interleaves it with participant discussion. See DS003-application-runtime-and-events.md and DS008-scripta-robo-collaboration.md.

In SCRIPTA paragraph mode, the document header centers the auxiliary Chapter N - Paragraph N position indicator, while the content context keeps only the actual chapter title.

SCRIPTA chapter controls expose paragraph creation as Paragraph +; chapter up/down use explicit reorder-list icons without an additional visible label.

Adding a SCRIPTA chapter or paragraph focuses its newly created stable element and scrolls it into view once the realtime projection arrives.
