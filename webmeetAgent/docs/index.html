WebMeet Agent Documentation

WebMeet Agent owns workspace meeting rooms, guest invite routing, LiveKit participant token issuance, AI dispatch metadata, room resources, and the Explorer WebMeet plugin. Under the runtime-v5 contract, each join resolves the current active signaling locator and obtains short-lived external relay credentials through the private Ploinky broker. Server-side Twirp calls use the private Router listener with body-bound current-generation assertions. Authenticated clients receive workspace room-list and roster events without reloading. WebMeet events use the central WEBMEET_EVENT_TYPES contract and the canonical room:type:base64url_payload format. Authenticated joins carry the workspace user id in participant attributes, and clients publish a sanitized avatar projection into the roster. Room exit shuts down local capture and remote playback before completing the leave flow.

Current implementation status: the WebMeet application and verification code implements the v5 flow, but the observed rootless Podman host-gateway mapping reaches the box outer-facing interface. A default managed-bridge WebMeet runtime therefore cannot reach private Router 8081 without violating the approved bind boundary. Private Twirp, TURN brokerage, and the fresh-stack media gates remain inactive and fail-closed pending Ploinky DS004 Question #8. There is no public-Router, direct-target, widened-listener, host-mode, or forwarding-sidecar fallback.

Before relay credentials expire and after browser network transitions, WebMeet resolves fresh join material and performs a controlled LiveKit disconnect, recreation, and rejoin. Microphone and camera state are restored; an active screen share stops and requires the user to press Share screen again because display capture requires fresh browser activation. The local release gate uses two distinct authenticated browser contexts and exercises real ScreenShare in both directions, with publication, remote video readiness, source-specific RTP growth, active non-relay UDP 7882 candidate-pair evidence in both browsers, unpublication, and redacted failure artifacts. Trace sanitization transforms JSON and Playwright NDJSON structurally, redacts dynamic cookie, participant, TURN, assertion, and CSRF material, preserves parseability, and post-scans textual archive members before attachment. The local gate does not claim the configured public address. Separate native Linux x64 and arm64 lanes prove the exact configured public IPv4 on UDP 7882, reject 7881 and private/discovered alternatives, and prove external relay UDP and TLS fallback.

WebMeet audio defaults to a browser-local automatic voice pipeline for users without saved preferences. It uses locally vendored RNNoise when supported, conservative adaptive gain and hum detection, standard browser processing as fallback, and local remote-participant volume normalization. Manual audio-control edits switch the draft from automatic to custom instead of limiting the user. No paid/cloud denoise service or per-minute audio processing is required, and raw audio is never persisted by diagnostics.

The DS specifications are the source of truth for contracts, runtime assumptions, media recovery behavior, and Ploinky invariants. Start with DS000-vision.md, DS001-coding-style.md, and the matrix before changing WebMeet behavior.
