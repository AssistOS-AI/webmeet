WebMeet Agent Documentation

The blackboard uses CRAP visual hierarchy: aligned control groups separated only by proximity and fine vertical rules, without visible group labels or card backgrounds; stronger contrast between shell, toolbar, and canvas; a trailing appearance control; and a concise empty-canvas prompt.

WebMeet Agent owns workspace meeting rooms, guest invite routing, LiveKit participant token issuance, AI dispatch metadata, room resources, and the Explorer WebMeet plugin. Live microphone, camera, screen share, Redis coordination, TURN/STUN, and production LiveKit TLS are owned by webmeetInfra/liveKitServerAgent. Authenticated clients receive workspace room-list and roster events without reloading. WebMeet events use the central WEBMEET_EVENT_TYPES contract and the canonical room:type:base64url_payload format; each event type declares whether it is persisted or realtime-only. Authenticated LiveKit joins carry the workspace user id in participant attributes, and clients publish a sanitized avatar projection into the WebMeet roster so remote cards can render profile avatars without reading another user's DPU My Space. Media-only LiveKit updates such as microphone and track changes preserve already projected avatars. Room exit shuts down local capture and remote playback before completing the leave flow. The optional self-hosted LiveKit AI worker runs as the separate webmeetLivekitAiAgent Ploinky agent. WebMeet chat treats provider-looking text such as @open-interpreter as ordinary meeting chat; provider routing belongs to AchillesCLI Copilot.

WebMeet audio defaults to a browser-local automatic voice pipeline for users without saved preferences. It uses locally vendored RNNoise when supported, conservative adaptive gain and hum detection, standard browser processing as fallback, and local remote-participant volume normalization. Manual audio-control edits switch the draft from automatic to custom instead of limiting the user. No paid/cloud denoise service or per-minute audio processing is required, and raw audio is never persisted by diagnostics.

The meeting chat composer exposes browser speech recognition as push-to-talk input for RoboTeam commands. When a participant enters a room, WebMeet requests pending browser microphone permission once and immediately stops the temporary permission stream, so the first push-to-talk gesture does not need to open the permission dialog. Permission refusal does not block room entry. An empty composer shows a microphone control; holding it inserts the /robo prefix immediately, displays interim recognition text, and enables transient Blackboard widget ordinals. Releasing the control finalizes and submits the command through the same authoritative chat command path as typed input. Typing any text restores the normal Send action. The Voice commands settings tab stores a browser-local recognition language preference in the existing WebMeet media settings; Automatic uses the browser language, while an explicit EU language applies from the next push-to-talk capture. This browser-scoped input does not change the published LiveKit microphone, persist audio, call the internal scribe STT service, or add a WebMeet speech endpoint.

Chat exposes attachments through a plus control aligned to the left of the composer input. Its WebSkel menu contains one Add file option and accepts any file up to 15 MB through the picker, clipboard paste, or drag-and-drop over the composer. Files can also be pasted or dropped directly at the desired logical position on the normal Blackboard canvas or any workspace preview in Show all. All entry points share one ordered publisher, so every successful upload creates the same durable chat message and one widget on the explicitly targeted workspace. Explorer recognizes PNG, JPEG, WebP, and GIF from their bytes and renders them as image widgets; other files render as reusable cards showing name, extension, MIME type, and size. File cards support move, resize, grouping, delete, cross-tab drag, and one-shot Copy/Cut/Paste; their contextual menu contains Download, Move, and Delete while intentionally omitting Settings and Rotate. The declarative Download action appears only in that menu, not inside the widget card. File widgets cannot be resized below 160 by 100 logical pixels, keeping their content inside the selection frame. Explorer stores verified images with their image extension and all non-images with an inert .bin extension, while a separate <assetId>.metadata.json record preserves the original filename and metadata for download. After publication, the uploader's browser opens and focuses its local Blackboard surface when necessary and immediately displays the returned projection without changing any peer layout. Existing images and rigid groups retain their SCRIPTA insertion behavior.

RoboTeam exposes workspace-backed SCRIPTA collaboration and agentic diagrams through one canonical blackboard event path. Natural /event and /robo instructions in any language run in an isolated, bounded MainAgent round and produce an atomic event list or an explicit natural-language semantic error without mutation. Every interpretation, repair, and verification response uses provider-native strict JSON Schema Structured Outputs rather than free-form JSON text; the same canonical schema covers actions, widget properties, diagram relations, SCRIPTA payloads, and semantic errors. The Blackboard owns revision ordering, shared semantic focus, groups, attached connections, labels, and history. Logical geometry is independent of browser viewport, and an empty board uses a shared 1200 by 800 frame. Lines and arrows expose four connection points on standalone widgets and complete groups; each end can independently snap, follow live move/resize/rotation, or detach back to a free endpoint. Ungroup preserves the last visible endpoint position, internal connectors remap through Copy/Cut/Paste and tab transfer, and connections never span tabs. As soon as the chat composer starts with /robo, transient ordinal badges let the participant refer to targets by number; each rigid group has one dedicated G<number> badge, its members have no separate badges, and ordinal or focused-group commands apply atomically to the whole group. After submission, a shared realtime status balloon shows who is editing and the terminal result. create is the only creation action; add, lock, unlock, client revisions, and caller-supplied provenance are rejected. Server-serialized mutations use last-edit-wins, increment revision for realtime ordering, apply the returned projection immediately, and never require optimistic conflict resync. Shapes render properties.label inside their SVG and attached lines follow widget geometry. Modifier-click or a marquee can combine independent widgets and any number of complete existing groups into one strict block with a contextual Move, Rotate, Export, Delete, and Ungroup menu; selecting one group member for composition includes its entire group. Resize remains available through the group outline handles. The selection overlay stays eight pixels outside the member bounds, including during resize previews, without changing persisted geometry. Export produces a local PNG with a transparent or solid board-theme background and does not mutate the blackboard. Group creation, merging, and transforms are atomic, preserve member relationships, and undo as one command. Full chat renders each sanitized semantic event with the human-readable workspace title captured by its audit, without private paths, opaque board ids, transport identifiers, or revisions. See DS003-application-runtime-and-events.md, DS008-scripta-robo-collaboration.md, and DS009-blackboard-agentic-diagrams.md.

The Blackboard is a shared multi-zone workspace rather than one fixed board. Its ordered tab strip synchronizes the active zone for every participant, supports mouse and ARIA keyboard navigation, uses double-click for inline tab renaming, commits the title when focus leaves the input, and animates directional changes as a reduced-motion-aware slide. Participants can create, reorder, and delete zones, move widgets, groups, file cards, or multi-selections between tabs through hover-and-drop, and open a local scrollable filmstrip whose previews miniaturize the real component types, styles, images, file metadata, and semantic content. During a normal full-size drag, holding the selection over another tab for 450 ms activates that tab while the gesture continues at document scope; a bounded outline then follows the pointer over the new canvas, and releasing inside it transfers the selection at the indicated position with the original grab offset. Releasing early or outside the canvas leaves the source unchanged. Existing groups appear inside one labelled outline whose hover and drag apply to the complete group, while standalone miniatures remain independently interactive. Miniature items and groups can be dropped at the chosen position in another workspace or back into their current preview for same-board repositioning; external files dropped on a preview are published at that exact logical point. Ctrl/Cmd+C copies the current widget, complete group, or multi-selection, Ctrl/Cmd+X marks it for a deferred move, and Ctrl/Cmd+V pastes into the active tab in normal mode or the focused filmstrip workspace. Right-clicking a selection exposes declarative Copy and Cut actions; after either action, right-clicking the current board, another active tab, or any filmstrip preview exposes Paste here at the exact clicked logical position. Copy creates server-generated widget and group ids and remaps internal connections through one atomic board-copy; Cut leaves the source unchanged until one atomic board-transfer succeeds. Every successful paste clears the local Copy/Cut clipboard, while a failed paste retains both the source and clipboard for retry. The singleton SCRIPTA projection is intentionally not copyable. Natural /robo commands receive the ordered tab catalog and can create, rename, reorder, activate, delete, or transfer to a workspace identified by its unique title or visible ordinal. Workspace structure and content mutations use one global atomic Undo/Redo history; tab activation is shared navigation and is not an undo step.

Blackboard connection indicators are centered along the four target sides and sit immediately outside, tangent to the widget or group border; the canonical connector endpoint itself remains exactly on that border. Group bounds ignore attached connectors whose geometry is derived from their endpoints, while free lines retain their geometry and groups made only from free lines remain valid connection targets. A line is pointer-interactive only along a narrow band around its visible segment, so its rectangular SVG bounds cannot block dragging a connected widget on the first gesture. Pressing and holding an unselected movable widget selects and drags it in that same first gesture; shared focus is deferred until release so a realtime focus projection cannot interrupt pointer capture.

In SCRIPTA paragraph mode, the document header centers the auxiliary Chapter N - Paragraph N position indicator, while the content context keeps only the actual chapter title.

SCRIPTA chapter controls expose paragraph creation as Paragraph +; chapter up/down use explicit reorder-list icons without an additional visible label.

Adding a SCRIPTA chapter or paragraph focuses its newly created stable element and scrolls it into view once the realtime projection arrives.
