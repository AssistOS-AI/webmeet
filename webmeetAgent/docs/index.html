WebMeet Agent Documentation

The blackboard uses CRAP visual hierarchy: aligned control groups separated only by proximity and fine vertical rules, without visible group labels or card backgrounds; stronger contrast between shell, toolbar, and canvas; a trailing appearance control; and a concise empty-canvas prompt.

WebMeet Agent owns workspace meeting rooms, guest invite routing, LiveKit participant token issuance, AI dispatch metadata, room resources, and the Explorer WebMeet plugin. Live microphone, camera, screen share, Redis coordination, TURN/STUN, and production LiveKit TLS are owned by webmeetInfra/liveKitServerAgent. Authenticated clients receive workspace room-list and roster events without reloading. WebMeet events use the central WEBMEET_EVENT_TYPES contract and the canonical room:type:base64url_payload format; each event type declares whether it is persisted or realtime-only. Authenticated LiveKit joins carry the workspace user id in participant attributes, and clients publish a sanitized avatar projection into the WebMeet roster so remote cards can render profile avatars without reading another user's DPU My Space. Media-only LiveKit updates such as microphone and track changes preserve already projected avatars. Room exit shuts down local capture and remote playback before completing the leave flow. The optional self-hosted LiveKit AI worker runs as the separate webmeetLivekitAiAgent Ploinky agent. WebMeet chat treats provider-looking text such as @open-interpreter as ordinary meeting chat; provider routing belongs to AchillesCLI Copilot.

WebMeet audio defaults to a browser-local automatic voice pipeline for users without saved preferences. It uses locally vendored RNNoise when supported, conservative adaptive gain and hum detection, standard browser processing as fallback, and local remote-participant volume normalization. Manual audio-control edits switch the draft from automatic to custom instead of limiting the user. No paid/cloud denoise service or per-minute audio processing is required, and raw audio is never persisted by diagnostics.

The meeting chat composer exposes browser speech recognition as push-to-talk input for RoboTeam commands. When a participant enters a room, WebMeet requests pending browser microphone permission once and immediately stops the temporary permission stream, so the first push-to-talk gesture does not need to open the permission dialog. Permission refusal does not block room entry. An empty composer shows a microphone control; holding it inserts the /robo prefix immediately, displays interim recognition text, and enables transient Blackboard widget ordinals. Releasing the control finalizes and submits the command through the same authoritative chat command path as typed input. Typing any text restores the normal Send action. The Voice commands settings tab stores a browser-local recognition language preference in the existing WebMeet media settings; Automatic uses the browser language, while an explicit EU language applies from the next push-to-talk capture. This browser-scoped input does not change the published LiveKit microphone, persist audio, call the internal scribe STT service, or add a WebMeet speech endpoint.

Chat exposes attachments through a plus control aligned to the left of the composer input. Its WebSkel menu currently contains one Add image option and accepts validated PNG, JPEG, WebP, and GIF images up to 15 MB through the file picker, clipboard paste, or drag-and-drop over the composer. Clipboard text accompanying images is not inserted. Multiple pasted or dropped images are published sequentially in source order, with independent errors that do not block later images. Explorer moves each staged upload into document-multimedia/webmeet/<roomId>/assets/<assetId>.<ext>; WebMeet then persists one chat attachment and one editable Blackboard image widget in the same room mutation. After publication, the uploader's browser opens and focuses its local Blackboard surface when necessary and immediately displays the returned projection without changing any peer layout. An existing image or rigid group can be inserted into the active SCRIPTA document from its contextual action or a /robo command. Individual images reuse their existing Explorer asset. A group is rendered once by the requesting browser, committed as a new room asset, and inserted as standard Markdown image syntax through Explorer's authoritative SCRIPTA CRDT mutation.

RoboTeam exposes workspace-backed SCRIPTA collaboration and agentic diagrams through one canonical blackboard event path. Natural /event and /robo instructions in any language run in an isolated, bounded MainAgent round and produce an atomic event list or an explicit natural-language semantic error without mutation. Every interpretation, repair, and verification response uses provider-native strict JSON Schema Structured Outputs rather than free-form JSON text; the same canonical schema covers actions, widget properties, diagram relations, SCRIPTA payloads, and semantic errors. The Blackboard owns revision ordering, shared semantic focus, groups, attached connections, labels, and history. Logical geometry is independent of browser viewport, and an empty board uses a shared 1200 by 800 frame. As soon as the chat composer starts with /robo, transient ordinal badges let the participant refer to targets by number; each rigid group has one dedicated G<number> badge, its members have no separate badges, and ordinal or focused-group commands apply atomically to the whole group. After submission, a shared realtime status balloon shows who is editing and the terminal result. create is the only creation action; add, lock, unlock, client revisions, and caller-supplied provenance are rejected. Server-serialized mutations use last-edit-wins, increment revision for realtime ordering, apply the returned projection immediately, and never require optimistic conflict resync. Shapes render properties.label inside their SVG and attached lines follow widget geometry. Modifier-click or a marquee can group widgets into a strict block with a contextual Move, Rotate, Export, Delete, and Ungroup menu; resize remains available through the group outline handles. The selection overlay stays eight pixels outside the member bounds, including during resize previews, without changing persisted geometry. Export produces a local PNG with a transparent or solid board-theme background and does not mutate the blackboard. Group transforms are atomic, preserve member relationships, and undo as one command. Full chat renders sanitized semantic events without private paths, transport identifiers, or revisions. In SCRIPTA paragraph mode, the document header centers the auxiliary Chapter N - Paragraph N position indicator, while the content context keeps only the actual chapter title.

SCRIPTA chapter controls expose paragraph creation as Paragraph +; chapter up/down use explicit reorder-list icons without an additional visible label.

Adding a SCRIPTA chapter or paragraph focuses its newly created stable element and scrolls it into view once the realtime projection arrives.
