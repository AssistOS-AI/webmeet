WebMeet Agent Documentation

WebMeet Agent owns workspace meeting rooms, guest invite routing, LiveKit participant token issuance, AI dispatch metadata, room resources, and the Explorer WebMeet plugin. Live microphone, camera, screen share, Redis coordination, and expiring TURN credential issuance are owned by webmeetInfra/liveKitServerAgent; the separate webmeetInfra/turnServerAgent owns Coturn relay operation and validates those credentials from their shared secret; and basic/web-publishing is the sole owner of browser-facing LiveKit signaling and its trusted TLS edge. WebMeet never holds or issues a TURN credential itself. Authenticated clients receive workspace room-list and roster events without reloading. WebMeet events use the central WEBMEET_EVENT_TYPES contract and the canonical room:type:base64url_payload format; each event type declares whether it is persisted or realtime-only. Authenticated LiveKit joins carry the workspace user id in participant attributes, and clients publish a sanitized avatar projection into the WebMeet roster so remote cards can render profile avatars without reading another user's DPU My Space. Media-only LiveKit updates such as microphone and track changes preserve already projected avatars. Room exit shuts down local capture and remote playback before completing the leave flow. The optional self-hosted LiveKit AI worker runs as the separate webmeetLivekitAiAgent Ploinky agent. WebMeet chat treats provider-looking text such as @open-interpreter as ordinary meeting chat; provider routing belongs to AchillesCLI Copilot.

The rootless network boundary is explicit: webmeetAgent, liveKitServerAgent, and web-publishing share webmeet-signaling; only liveKitServerAgent and turnServerAgent share webmeet-turn. Ploinky derives the lowercase service identities from canonical agent ids, so manifests declare no network aliases. Web Publishing reaches LiveKit at http://livekitserveragent:7880 and does not depend on a fixed host-gateway address.

WebMeet audio defaults to a browser-local automatic voice pipeline for users without saved preferences. It uses locally vendored RNNoise when supported, conservative adaptive gain and hum detection, standard browser processing as fallback, and local remote-participant volume normalization. Manual audio-control edits switch the draft from automatic to custom instead of limiting the user. No paid/cloud denoise service or per-minute audio processing is required, and raw audio is never persisted by diagnostics. Opt-in media diagnostics retain only useful aggregate context after redacting sensitive fields, serialized or recursively percent-encoded credential assignments, URL userinfo, private-key material, SDP, ICE candidates, and TURN/STUN URLs. Percent decoding proceeds to convergence under a strict work bound and redacts the entire string if that bound is reached.

The DS specifications are the source of truth for contracts, runtime assumptions, media recovery behavior, and Ploinky invariants. Start with DS000-vision.md, DS001-coding-style.md, and the matrix before changing WebMeet behavior.
