# WebMeet Meeting Secretary

`webmeetScribeAgent` is the text-only LiveKit worker for cumulative WebMeet notes. It receives retry-safe directed final browser transcripts, validates their LiveKit authors against the admitted room roster, stores a temporary encrypted recovery journal, and invokes the strict Achilles `meeting-notes` skill with the room's editable title-and-chapter structure and the complete discussion represented by the current document, cumulative semantic memory, and uncompacted transcript on every revision. The first accepted transcript ensures that an active discussion with no document immediately receives one empty SCRIPTA document. Output-format and analysis rules remain internal to the skill. Markdown safety and chapter structure are validated before persistence; lexical topic matching is not used. A full public SCRIPTA snapshot is requested only for a new analysis checkpoint, while ordinary heartbeats remain lightweight. Validated compacted prefixes are removed from raw recovery state, oversized backlogs are processed as bounded sequential checkpoints, and authoritative realtime activity phases expose queued, analyzing, updating, and retrying work in the room UI. A reset cancels the obsolete worker's retries, removes its journal, and disconnects it from the room.

The LiveKit worker health listener uses the standard `PORT` value supplied by its Ploinky profile. Like the other Explorer agents, it runs on Ploinky's managed bridge and receives the generated Router descriptor and agent credential. A loopback-only WebSocket authority relay uses the runtime-generated physical Router URL and request authority to preserve the `node-authority-v1` contract for the LiveKit SDK; it accepts only the manifest-declared LiveKit signaling prefix. The worker shares the canonical `LIVEKIT_API_KEY` and `LIVEKIT_API_SECRET` credentials with WebMeet and the LiveKit server.

The authoritative room, Blackboard, and SCRIPTA contracts remain in `webmeetAgent/docs/specs/DS010-meeting-secretary.md`.
