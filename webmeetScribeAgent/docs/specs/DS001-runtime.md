# DS001 - Meeting Secretary Runtime

The worker accepts only dispatches containing a meeting id, connects without an audio pipeline, and advertises `webmeetMeetingSecretary=true` and `webmeetAgentType=meeting_secretary`. Reliable final transcript packets are accepted only from identities returned by the authoritative WebMeet session heartbeat.

At 45 seconds or 300 new words, the worker invokes `meeting-notes` with the current Markdown document, cumulative semantic memory of compacted history, the uncompacted chronological transcript, and the room's editable title-and-chapter structure. It never submits an isolated time window. Before each call it captures an immutable transcript checkpoint and requests one public SCRIPTA collaboration snapshot; ordinary lease/activity heartbeats do not fetch the full document. Text received during analysis stays pending for the next sequential revision. A generated Markdown revision must finish its durable document apply before a later checkpoint can invoke the LLM. Transient provider failures retry the same durable checkpoint with bounded backoff, while an unchanged transcript alone never triggers an LLM call. Room-empty or disabled-note finalization applies an already generated pending document but never forces an analysis checkpoint whose retries are exhausted or whose failure is terminal. The skill returns complete Markdown, never JSON or SCRIPTA metadata. The default editable value describes only the seven-section meeting-note structure; response-format, holistic reconciliation, attribution, deduplication, and SCRIPTA-safety instructions remain internal to the skill. Organizers can edit the structure maintained by subsequent revisions. Output validation requires non-empty bounded Markdown, exactly one leading H1, the configured H2 chapter order, and no SCRIPTA metadata. It does not perform lexical topic matching. Compacted memory is validated only as a non-empty bounded structured value. Memory compaction runs only when already-published history exceeds the configured context budget; compacted prefixes are removed from raw in-memory and encrypted state, and an oversized pending backlog is divided into sequential bounded checkpoints. Compaction cannot move past the analyzed cursor or consume discussion that is waiting for its first visible document revision. Normal incremental revisions use one holistic document inference instead of an unconditional memory pass followed by a document pass. Model routing remains the responsibility of the agent and Soul Gateway configuration. The normal SCRIPTA Markdown CRDT layer applies text replacements through Automerge text operations, merges concurrent browser insertions, remaps retained inline images, preserves private structural metadata, and broadcasts the document revision. Metadata-free model input removes only individually parsed SCRIPTA JSON comments; ordinary user-authored HTML comments and the content between comments remain intact. Revisions are applied sequentially through delegated internal MCP tools. A server reset cancels pending retries, deletes the obsolete journal, and disconnects that worker. The encrypted journal is deleted 15 minutes after successful finalization or purged after 24 hours if recovery never succeeds.

The worker publishes realtime, non-persistent activity phases through the authoritative WebMeet control plane: `listening`, `queued`, `analyzing`, `updating`, and `retrying`. These phases describe actual journal and analysis state and allow the room UI to show visible progress without inventing a client-side editing animation.
